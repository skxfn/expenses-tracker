# Интеграция дизайна «Образцы» в «Траты»

Для разработчика, который переносит утверждённый дизайн (2026-10-09) в `App/` и `Packages/ExpenseCore`. До начала прочитать `AGENTS.md` (решения и ловушки проекта — обязательно), затем этот файл и `DESIGN.md`.

**[проверить]** — поведение не подтверждено документацией Apple/context7 или зависит от устройства. Проверить спайком или на iPhone с iOS 27 до того, как на это опираться. Остальные API сверены по developer.apple.com, минимальная iOS указана в скобках, если она важна. Deployment target — iOS 26: всё из iOS 26.0 можно использовать без `#available`. API из 26.1+ и 27 требуют проверки версии.

Коротко:
- Переписываются View и `App/Shared`. `@Observable`-модели (`ExpenseFormModel`, `StatisticsModel`, `BackupModel`, `ImportSession`, `CategoryFormModel`) остаются и расширяются. Все изменения данных идут через `ExpenseStore` (AGENTS.md).
- В данных три большие задачи: `SchemaV2` (подкатегории), резервная копия формата 2 с чтением формата 1, миграция цветов, иконок и имён по `design/migration.json`.
- Хром делается на системном Liquid Glass. CSS-рецепты в `design.json` служат эталоном для сверки со скриншотом, воссоздавать их не нужно.
- Тексты берутся только из `design/copy.json` → `final`. Новые строки не придумывать.

Как разрешать конфликты:
- **Текст на макете против `copy.json`**: прав `copy.json`. Тексты в макетах и картинках `design/mockups/` уже приведены к `final`, но строк из `copy.json`, которых в макетах нет (пустые состояния, ошибки, часть VoiceOver), на картинках не видно.
- **Число в `DESIGN.md` против `design.json`**: прав `design.json`. Пример: в `DESIGN.md` третья светлая ступень Шалфея — `#83CEA3`, в `design.json` — `#85D2A5`, и формула из `DESIGN.md` даёт именно `#85D2A5`.
- **Макет против правила `DESIGN.md`**: по старшинству прав макет. Исключение — известные расхождения из раздела 8: там нужно решение владельца. Если ждать нельзя, делать по рекомендации из раздела 8 и держать выбор в одном месте (компонент или константа), чтобы потом поменять одной правкой.
- **Демо-данные макетов** местами не сходятся между экранами (сумма «Кафе» и др.). Это иллюстрация, а не спецификация и не тестовые данные.
- `Swatch-*`, `Sheet-*`, `Ultra-*` на холсте устарели (AGENTS.md).

### 3.2 Цвета: код, а не Asset Catalog

| Критерий | Asset Catalog (colorset) | Код (`UIColor(dynamicProvider:)`, iOS 13) |
|---|---|---|

Роли (Правило тинта): насыщенный тон — только мелким (иконка, штрих 2–3, сегмент, образец, плитка). Площади крупнее плашки 36 — tint с deep-иконкой. В тёмной: плашка — darktint, иконка — цветом tint (`design.json` → `icons.dark`).

**Ступени подкатегорий**:
- **Какая ступень.** Логика в Core: индекс подкатегории среди сестёр по порядку из раздела 8, п. 3 (рекомендация — по созданию). Ступень = `index % 5`: шестая подкатегория повторяет первую ступень (`cat.shades.overflow`).
- **Каким цветом.** Брать таблицы, а не считать OKLCH в рантайме:
  - тёмная — `colorMeta.<tone>.subcategoryShadesDark` (5 значений; правило — `darkTheme.stepsRule`);
  - светлая — `colorMeta.<tone>.subcategoryShades` (**только 3 значения**). Формула `DESIGN.md` (L +0,09, C ×0,93 на ступень, оттенок тот же) воспроизводит ступени 1–3 из `design.json` с точностью ±1 по каналу. Но 4-я и 5-я ступени по ней уходят в белый: к листу 1,0–1,9:1, у Краплака, Киновари, Абрикоса, Ультрамарина и Аметиста — `#FFFFFF`. Макет `11-category` рисует для Абрикоса другую лесенку (`#BE7C30 #D89957 #EFB478 #FAC998 #FFDAB6`), и её третья ступень не совпадает с `design.json`. Это открытый вопрос (раздел 8, п. 9).
- **Подписи на ступенях.** Светлая — deep-оттенок категории; тёмная — night-ink.
- **«Без подкатегории».** Штриховка 45°: основной тон 1,4 / tint 2,1 (шаг 3,5) — `extensions.hatch`. В тёмной — основной тон (у Пиона pion-night) по darktint. Один компонент `HatchFill` на `Canvas` (iOS 15) или `Shape` с полосами под `clipShape`.

**Аура.** 2–3 пятна `EllipticalGradient` (iOS 15) tint-цветов крупнейших категорий периода, альфа 0,5–0,9, верхняя треть экрана (пример — `extensions.aura.example`). В тёмной — darktint. Это фон экрана, не стекло. В шите записи аура в цвет выбранной категории, над клавиатурой.

### 4.2 `SchemaV2` (эскиз)

```swift
public enum SchemaV2: VersionedSchema {
    public static let versionIdentifier = Schema.Version(2, 0, 0)
    public static var models: [any PersistentModel.Type] { [ExpenseCategory.self, Expense.self] }

    @Model public final class ExpenseCategory {
        @Attribute(.unique) public var id: UUID
        public var name: String
        public var iconName: String        // имя MingCute
        public var colorHex: String        // основной тон «Гуаши»; у подкатегории = hex родителя, UI его не читает
        public var sortOrder: Int
        public var isArchived: Bool
        public var createdAt: Date
        public var parent: ExpenseCategory? // nil — категория верхнего уровня
        @Relationship(deleteRule: .cascade, inverse: \ExpenseCategory.parent)
        public var children: [ExpenseCategory] = []
        @Relationship(deleteRule: .nullify, inverse: \Expense.category)
        public var expenses: [Expense] = []
        // init …
    }
    @Model public final class Expense { /* поля как в V1; category — категория или подкатегория */ }

```

Глубина — один уровень. До 15 категорий верхнего уровня, подкатегорий сколько угодно, трата ссылается на любой уровень. Цвет подкатегории не хранится: он выводится из тона родителя и номера ступени.

### 4.3 Миграция V1 → V2

```swift
public enum ExpenseMigrationPlan: SchemaMigrationPlan {
    public static var schemas: [any VersionedSchema.Type] { [SchemaV1.self, SchemaV2.self] }
    public static var stages: [MigrationStage] {
        [.custom(fromVersion: SchemaV1.self, toVersion: SchemaV2.self,
                 willMigrate: nil,
                 didMigrate: { context in try LegacyCatalogMigration.apply(in: context) })]
    }
}
```

- `MigrationStage.custom(fromVersion:toVersion:willMigrate:didMigrate:)` (iOS 17). Сама схема меняется совместимо (добавлено необязательное отношение), `didMigrate` нужен для замены значений. Стадию держать в вычисляемом `stages`: в Swift 6 глобальная `static let` с не-`Sendable` значением даст ошибку изоляции.
- `apply(in:)` для каждой категории: `colorHex` — по `migration.json` → `colors` (иначе `colorFallbackRule`), `iconName` — по `icons` (иначе `iconFallback`), имя — по `defaultCategories` строго по `defaultCategoriesRule` (переименовывать только непереименованные и только если новое имя свободно). Таблицы не пересекаются (старые hex/SF ≠ новые hex/MingCute), поэтому повторный проход ничего не меняет.
- Все категории V1 становятся категориями верхнего уровня. **В V1 не было лимита и уникальности цвета**: у пользователя может оказаться больше 15 категорий или повторяющиеся тона. Данные не трогать, лимит только запрещает создавать новые (раздел 8, п. 12).
- Тест на маке (`swift test`): создать хранилище V1 во временной папке с образцами данных, открыть фабрикой V2, проверить родителей, цвета, иконки и имена. [проверить] на копии реальной базы с устройства (самоссылочное отношение в кастомной стадии). Перед установкой сборки с V2 сохранить резервную копию.

### 4.5 Резервная копия: формат 2 с чтением 1

- `BackupFormat.currentVersion = 2`. В `CategoryRecord` добавляется `parentID: UUID?`. Иконки — имена MingCute, цвета — тоны «Гуаши».
- `BackupImporter.decode`: прочитать `formatVersion`. `1` → декодировать как v1 и перевести в v2: `parentID = nil`, цвета и иконки по `migration.json`, имена **не** менять (`import.v1` говорит только про цвета и иконки) — и поставить в отчёт флаг «из прошлой версии». `2` → как есть. `> 2` → `newerFormat`, остальное → `unsupportedFormat`. Сейчас `decode` и `validate` требуют `version == currentVersion` — исправить в обоих местах.
- Новые проверки: `parentID` есть в файле, родитель верхнего уровня, нет ссылки на себя, нет глубины > 1. Применение в два прохода: сначала категории верхнего уровня, потом подкатегории со связью, потом траты. Откат при ошибке — как сейчас, через `rollback()` и повторную выборку (ловушка AGENTS.md).
- **Ошибки.** `BackupError.unreadableFile(details: String)` заменить на причины (`notJSON`, `notBackup`, `missingField`, `badValue`, `badDate`) с текстами `error.backup.detail.*`. Тексты `duplicateCategoryID` / `duplicateExpenseID` содержат UUID — в UI идут `error.backup.duplicate*` без UUID.
- **Имя файла** — «Траты 2026-10-09.json» (`app.backupFileName`). В `.fileExporter` передавать без расширения (ловушка AGENTS.md). Даты — только через `BackupFormat`.
- Тесты: файл v1 → импорт → v2; v2 → экспорт → импорт без изменений; файл формата 3 → `newerFormat`.

### 4.6 Статистика: категории и подкатегории

- **`ExpenseRecord`.** Добавить `groupID: UUID?` (категория верхнего уровня). `categoryID` по-прежнему лист: категория или подкатегория. Трата «без подкатегории» — `categoryID == groupID` у категории, у которой есть подкатегории. Снимок: `groupID = expense.category?.parent?.id ?? expense.category?.id`.
- **`StatsCategoryFilter`.** Добавить `.group(UUID)` — категория со всеми подкатегориями. Раскрытие в статистике фильтрует все блоки (пометка `viz.drill.filter` «только Продукты»).
- **Разбивка** (имена — предложение): `groupBreakdown(for:records:) -> [StatsGroupShare]`, где у каждой категории есть `subcategories: [StatsCategoryShare]` и `unassignedMinor` («без подкатегории»). Доля категории — от итога периода, доля подкатегории — от итога категории («69% категории»). Метка «подкатегорий нет» зависит от каталога, а не от трат: её проставляет UI.
- **«Ещё N».** Чистая функция `fold(_:threshold: 0.03, minimumCount: 2)`: категории < 3 % сворачиваются, только если таких хотя бы две. Свёрнутые доступны через список. VoiceOver — `viz.more.a11y`.
- **Порядок.** Списки и «Полосы» — по сумме (текущий `isOrderedBefore`). Круги («Кольцо», «Солнце») — по оттенку: индекс тона в `GouachePalette`, при одинаковом тоне по сумме. Подкатегории внутри категории — в порядке ступеней.
- **Без категории** — отдельная строка. Внешний вид не задан (раздел 8, п. 10).

### 4.7 Период и сравнение

- `StatsPeriod.custom` и сдвиг на длину диапазона (`previous` / `next`) уже есть. Правило «› неактивна, если следующий диапазон целиком в будущем» уже реализовано в `StatisticsModel.canShowNext` (`period.interval.end <= now`). Перенести в общий `PeriodSelection`.
- Сегмент: `День · Неделя · Месяц · Год · Свой`. «Свой» без выбранного диапазона открывает шит «Период», с выбранным — переключает на него. ▾ в шапке открывает тот же шит (раздел 8, п. 2).
- **Заголовок.** Нужна структура «основная часть + вторичная» («5–7» + «окт»), а не одна строка. Текущий `StatsPeriod.title(…)` даёт системное «6–12 окт.» с точкой — это противоречит D7. Заменить своим форматтером (§5.2), `StatisticsPeriodTitleTests` обновить.
- **Сравнение «к той же дате»** (D5). Сейчас `summary` сравнивает с **целым** прошлым периодом — это нужно изменить:
  - идущий период (`contains(now)`): `n` — номер сегодняшнего дня в периоде (с 1). Сравнивать с первыми `min(n, длина прошлого)` днями прошлого периода. 31 октября → весь сентябрь, 30 марта → весь февраль, «День» → весь вчерашний. В високосный год у года расхождение на 1 день — допустимо, зафиксировать тестом;
  - прошедший период — с целым прошлым («в августе», «накануне», «в 2024»);
  - свой период — с предыдущим диапазоном той же длины («чем за 2–4 окт»).
- **Фраза** (`home.compare*`, `range.compare`, `stats.compare`):
  - знак разницы → «больше» / «меньше»;
  - разница от 1 000 Br — целыми рублями, без «≈»;
  - прошлый ноль → `home.compare.noPrev`;
  - почти ноль → `home.compare.same` (порог не задан — раздел 8, п. 11).
  - Формы «вчера / на прошлой неделе / в прошлом году» и названия месяцев в предложном падеже («в августе») — свои таблицы (§5.2).

### 4.8 Темп, дни недели, тепловая карта, топ

- **Прогноз.** `итог × дней_в_периоде / прошло_дней` в `Int64` через `divideRounded`. Только для идущих недели, месяца и года. Кривые — существующий `cumulativeComparison` + прямая от сегодня до конца. Подписи — `stats.pace.*`; «к воскресенью» зависит от `calendar.firstWeekday`. Для прошедшего периода — «итог за сентябрь». Для «Дня» и «Своего» не задано. Округление «≈ 1 600» не задано (раздел 8, п. 11).
- **Привычки.** Существующий `weekdayAverages` (показывается для месяца и года, `showsWeekdays`). Выводы: максимум — «по пятницам» (дательный мн.ч., своя таблица); будни против выходных — средние пн–пт против сб–вс, иначе «почти поровну». Порог не задан.
- **Тепловая карта и календарь.** Дневные суммы — существующий `timeSeries(for:records:step: .day)` за год или месяц. Пороги шкалы в макете — пример на демо-данных, правила нет (раздел 8, п. 11). Сумма в клетке — `cal.cell.amount` (§5.2). «больше всего 2 окт» — день с максимумом.
- **Топ.** Существующий `topExpenses`. Строка как в каноне ленты (раздел 8, п. 6).

### 4.9 Запись, удаление, настройки вида

- **Частые категории** — 6 образцов + «Все». Правило не задано. Предложение: листья (категория или подкатегория) по числу трат за 60 дней, при равенстве — по свежести, дозаполнять по `sortOrder`, архивные не показывать. Выбранный во «Всех категориях» лист замещает 6-й образец.
- **Быстрые суммы** прибавляют `N × 100` minor к введённой сумме, а не заменяют её. Пустое поле → `N`. Защита от переполнения `Int64`. Метод в `ExpenseFormModel`, поле перезаписывается через `editingString`.
- **«Ещё одна»** = сохранить → сбросить сумму и заметку, **дату оставить** (пачка за прошлый день). Категорию — раздел 8, п. 14. Клавиатура остаётся. Пакет `[(id, amountMinor)]` живёт в `ExpenseFormModel` до закрытия шита. Пилюля — плюрализация + сумма в формате ячейки. Объявление — `add.saved.a11y`.
- **Отмена удаления.** `PendingDeletion` в App: строка сразу скрывается фильтром по id, хранилище не трогается. `ExpenseStore.deleteExpense` вызывается по таймеру 4 с (пауза под пальцем), при `scenePhase == .background` или при следующем удалении. «Отменить» снимает пометку — без повторной вставки в SwiftData. Свойства удалённой модели не читать: строку тоста строить из снимка (ловушка AGENTS.md). «Удалить» в правке закрывает шит и показывает тост на экране под ним.
- **«Повторить»** (свайп) → `addExpense` с теми же суммой, категорией и заметкой и датой «сейчас».
- **Настройки вида.** `@AppStorage(SettingsKeys.homeOverviewStyle)` — «Плитки» по умолчанию; вид в статистике тоже запоминается (`statsCategoryView`). Тап по плитке или сегменту на главной открывает «Статистику» с **тем же периодом** и раскрытой категорией (рекомендация).

### 5.1 `copy.json` → String Catalog

- `App/Resources/Localizable.xcstrings`, исходный язык `ru` (`developmentLanguage: ru` в `project.yml`). Плюрализация — «Vary by Plural»: для русского Xcode добавит формы one / few / many / other (документация Xcode).

- **Ловушка разделителей.** В `final` «·» и «/» бывают двух видов:
  - перечисление **вариантов** — разбить на ключи `<id>.<вариант>`: `header.title.day` «Сегодня · Вчера · 6 окт», `home.empty.firstRun` (заголовок · строка), `add.discard` (вопрос / кнопка / кнопка);

- Удалить строки из `dropped` и устаревшие тексты: «Расходы», «Добавить расход», «Не получилось», «OK» латиницей, «Экспортировать в файл» и т. п.

### 5.2 Типографика текста

| Правило | Как в коде |
|---|---|
| Неразрывный пробел: число + Br, число + слово, внутри даты, после «≈», в разрядах, перед «—» и «–» | В строках каталога уже стоит. В выводе форматтеров [проверить], какой пробел даёт `FormatStyle` для `ru` (U+00A0 или U+202F), при необходимости нормализовать в одном месте |
| ё, «ёлочки» / „лапки“, «…» одним знаком, «—» с пробелами, «–» в диапазонах | только в каталоге, руками не собирать |
| **Деньги**: ячейки, плитки, строки, топ | всегда 2 знака, без «Br»: «38,00» |
| **Деньги**: во фразах | с «Br», нулевые копейки отбрасываются: «на 38 Br меньше» (как текущий `MoneyFormatter.string`) |
| **Деньги**: прогноз и сумма в шите периода | «≈ 1 600 Br» |
| **Деньги**: клетка календаря (`cal.cell.amount`) | < 1 000 — «64,10»; 1 000–9 999 — «1 234»; ≥ 10 000 — «12 тыс» |
| Проценты (D7) | целые, слитно: «35%», меньше 1 — «<1%». Свой форматтер: системный `ru` даёт «35 %» |
| Короткие даты (D7) | свои, без точки: «8 окт», «чт, 8 окт», «5–7 окт», «28 сен – 4 окт»; день недели с заглавной только в начале строки. Год — только если не текущий. Таблица сокращений своя; для мая в датах («8 мая») формы в `copy.json` нет — согласовать |
| Полные даты | «Четверг, 8 октября» — системный wide-формат с заглавной буквы |
| Падежи, которых нет в системе | свои таблицы: «в августе» (предложный), «по пятницам» (дательный мн.ч.), «к воскресенью», «за сентябрь» |
| Имена категорий | не склоняются (голос `copy.json`): только после тире, двоеточия, в начале строки или в «ёлочках» |
| Выделение в SF-фразе | интерполяция `Text` внутри `Text`: `Text + Text` устарел в iOS 26 (Apple: «Use string interpolation on Text instead») |

### 5.3 VoiceOver

Строки — раздел `voiceover` в `copy.json`. Правила:
- имя — что это и значение, подсказка — глагол в 3-м лице («Открывает…»);
- без «нажмите», «тап» и «·»;
- данные описываются суммой, а не цветом или светлотой;
- строки ленты и плитки — один элемент (`.accessibilityElement(children: .combine)`) с действиями «Удалить», «Повторить сегодня» (`accessibilityAction(named:_:)`, iOS 16);
- суммы — словом «рубль» (раздел 8, п. 7).

### 5.4 Длинные строки (`risk` в `copy.json`)

- Пользовательское имя обрезается многоточием в конце; фраза вокруг не переносится.
- Запасные варианты делать через `ViewThatFits` (iOS 16):
  - шапка через месяц/год — «28 сен – 4 окт», при переполнении «28.09–4.10»;
  - `cal.day.title` — «Воскресенье, 30 сентября» → «Вс, 30 сентября»;
  - `period.range.meta` — при переполнении убрать сумму, дни оставить;
  - `cal.legend.items` при трёхзначных порогах — «<125»;
  - `cat.unarchive` в узкой кнопке — «Из архива».
- Шапка своего периода — `minimumScaleFactor` (DESIGN.md).
- Кнопка свайпа «Повторить» шире 74 px — iOS растянет её сама.

## 6. Доступность и платформа

- **Dynamic Type.** Макеты нарисованы на абсолютных координатах 390×844 — это геометрия только для размера по умолчанию. Вёрстка — стеками, `Grid`, `ViewThatFits`, никаких `position`. Unbounded — через `relativeTo` (§3.3), размеры плашек и иконок — `@ScaledMetric`. Плотные места, где размер жёстко задан (таб-бар, сегмент из 5 пунктов, клетки календаря, образцы 46×60, подписи плиток), ограничить `.dynamicTypeSize(...DynamicTypeSize.accessibility1)` (iOS 15) и добавить `accessibilityShowsLargeContentViewer()` (iOS 15). В строках ленты на крупных размерах сумма уходит под текст — логика есть в текущем `CategoryAmountRow`.
- **Reduce Motion / Transparency** — §3.6 и §3.4. Ведёт ли себя зум шита при Reduce Motion как кроссфейд — [проверить].
- **Цели касания ≥ 44.** Кольцо — невидимые цели 44 над сегментами. Клетки тепловой карты меньше 44, поэтому карта — один элемент с описанием (`stats.year.a11y`), а не сетка кнопок.
- **Графики.**
  - «По дням» — скраббинг через `chartXSelection(value:)` (iOS 17) с подсказкой дня (`stats.days.tip`). Это же решает узкие подписи: на оси только 1, 8, 15, 22, 29.
  - Кольцо на Swift Charts — `chartAngleSelection(value:)` (iOS 17).
  - Описание графиков — `accessibilityChartDescriptor(_:)` (iOS 15) или подписи марок из `stats.days.bar.a11y`.
  - Свои визуализации («Плитки», «Полосы», «Солнце», «Кольцо») — `Shape`/`Canvas`, каждая часть — кнопка с подписью из `copy.json`. Порядок VoiceOver — по сумме, как во фразе `stats.sun.a11y`.
- **Системные и свои элементы:**

| Элемент | Рекомендация |

## 8. Открытые вопросы владельцу

Подпись не мельче Unbounded 15/500. Вне визуализаций эти пары для текста не использовать. Зафиксировать в `DESIGN.md`.
2. **Два входа в шит периода** (▾ в шапке и пункт «Свой») против правила `DESIGN.md` «один способ выбрать период». *Рекомендация:* оба ведут в один шит, правило переписать: «один шит выбора периода».    - (в) свой бар в `GlassEffectContainer` поверх `TabView` со скрытой системной панелью (`.toolbar(.hidden, for: .tabBar)`).
   - *Рекомендация:* спайк (а), при неудаче — (в); (б) не использовать. Свой «‹ Траты» в настройках заменить системной кнопкой «Назад».

Найдено при подготовке этого документа:

8. **Лицензии.** В `copy.json` есть только MingCute (`settings.licenses`, строка «Лицензия иконок»). Нужен текст для Unbounded (OFL) и, вероятно, переименование строки в «Лицензии». *Рекомендация:* одна строка «Лицензии», экран с двумя блоками и полными текстами.
